# simple caption tool

Windows向けの独立したPySide6アプリです。キャラクターLoRA／画風LoRA用のキャプションを、ローカルVLMで解析・編集・出力します。

## 起動

このフォルダーの **`simple-caption-tool.cmd` をダブルクリック**してください。GUIはコンソールなしのPythonで別プロセスとして起動し、起動用のコマンド画面は閉じます。初回セットアップ中やセットアップ失敗時はコマンド画面を表示します。

別のPCではWindows x64とPython 3.11以降が必要です。初回起動時にGUI依存関係を導入します。現在はソース実行版で、Python不要の配布用EXEはまだ作成していません。

手動セットアップ:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m captioner
```

## 使い方

1. 「画像フォルダーを開く」で画像のあるフォルダーを選択します。サブフォルダーも対象です。対応形式はPNG/JPEG/WebP/BMP/TIFF。既存の同名UTF-8 TXTは編集済みキャプションとして取り込みます。
2. 学習対象、自然文／タグ／混合、トリガー、解析モデルを選択します。出力キャプションは英語です。編集欄とTXTは日本語にも対応します。
3. 「未解析・失敗を解析／再開」を押します。初回は推論エンジンと選択モデルを自動取得し、内部で起動します。サーバーの操作は不要です。
4. サムネイルを選び、キャプションを編集します。Ctrl/Shiftで複数選択できます。編集内容と解析結果は画像フォルダー内の `.captioner/project.json` に自動保存されます。
5. 「JSONから再生成」で解析済みの観測から出力形式・トリガーを変更できます。この操作はVLMを呼びません。「選択画像を再解析」は画像からVLM解析をやり直す操作です。
6. 「画像と同名のUTF-8 TXTを一括出力」で、画像の隣に拡張子だけを `.txt` に替えたファイルを出力します。

キャラクター用は既定で固定外見を省略し、衣服・ポーズ・背景・画材などを記述します。固定外見も記述したい場合はチェックを入れます。画風用は被写体・外見・構図などを記述し、学習したい画風の説明を省きます。これらはモデルへの指示であり、実際の出力は確認・編集してください。

手動編集済みキャプションは再生成・再解析で保護されます。上書きしたい場合のみ専用チェックを入れてください。既存TXTも既定でスキップします。TXT上書きを有効にした場合は `.captioner/txt-backups/` に変更前のファイルを保存します。同じフォルダーの `a.png` と `a.jpg` のように出力名が衝突する場合は、出力前に停止します。

## 最後に使った設定と全画像の再解析

モデル、学習対象、出力形式、トリガーと抽出方法、固定外見の記述、GPU層数、画像サイズ、手動編集とTXTの上書きチェック、表示フィルターをアプリ全体の設定として自動保存します。フォルダー未選択でも保存され、次回起動時に復元します。保存場所はキャッシュ内の `preferences.json` です。変更後400msと通常終了時に保存します。

新しい画像フォルダーは画面の設定を引き継ぎます。既存の画像フォルダーは、そのフォルダーのプロジェクトJSONに保存された解析・出力設定を優先します。前回の画像フォルダーはフォルダー選択ダイアログの開始場所として記憶し、自動で開いたり解析したりはしません。

設定未保存時の初期モデルは **JoyCaption** です。設定が保存されている場合は、最後に選んだモデルを復元します。

「すべての画像を再解析」は、選択や表示フィルターにかかわらず、画像が存在する全件を解析し直します。解析済みも対象です。手動編集キャプションは専用チェックが有効な場合だけ置き換え、既定では保護します。以前の応答はJSON履歴に保持します。TXTの更新は引き続き一括出力ボタンで行います。

## ファイル名から画像ごとのトリガーを付ける

「トリガーの指定」を「ファイル名の先頭を使う」に切り替え、先頭から使う長さと単位（文字／単語）を指定します。何番目の単語かではなく、先頭からの範囲です。拡張子とフォルダー名は含めません。

- `akari_school_001.png` → 先頭5文字: `akari`
- `akari_school_001.png` → 先頭1単語: `akari`、先頭2単語: `akari_school`
- `mio_casual_002.png` → 先頭1単語: `mio`

単語は既定で空白・`_`・`-`で区切ります。「単語の区切り」欄で記号を変更できます。選んだ範囲内の元の区切りは保持します。指定数より短い名前は、その名前全体を使用します。選択画像の抽出結果は「適用例」に表示します。共通トリガーの入力内容も保持され、モードを戻すと再び使えます。

既存の解析結果には「JSONから全件を再生成」で反映します。手動編集済みも変更する場合は「手動編集済みも再生成・再解析で上書きする」を有効にしてください。TXTへの反映は続けて一括出力してください。既存TXTを更新する場合はバックアップ付き上書きのチェックも必要です。

## 初回取得とローカル処理

- 推論エンジン: llama.cpp **b11887 / Windows CUDA 12.4 x64**。本体＋CUDAランタイムの圧縮ファイルは約0.67GB。
- Qwen: Huihui Qwen3-VL-4B abliterated **Q4_K_M＋F16 mmproj**、合計約3.33GB。
- JoyCaption: Beta One **Q4_K＋F16 mmproj**、合計約5.80GB。現在の初期モデルです。
- ダウンロード先はアプリ内 `.local-cache/`。環境変数 `LORA_CAPTIONER_CACHE` で変更できます。展開後のエンジンもあるため、空き容量はQwenのみで8GB以上、両候補で15GB以上を目安にしてください。
- 配布元のコミット／リリース、ファイルサイズ、SHA-256は `captioner/catalog.json` に固定しています。中断時は `.part` を保持し、再実行で取得を再開します。
- 外部通信はモデル・推論エンジン・初回Python依存関係の取得に使用します。画像・キャプションの外部送信機能やクラウドAPI設定はありません。
- 画像はEXIF回転補正後、最大辺768／1024／1536pxへ縮小してメモリ内で処理し、認証付きの `127.0.0.1` のみに渡します。元画像は変更しません。
- 解析バッチ終了時に内部推論プロセスを終了します。中止はダウンロード中ならチャンク単位、推論中なら現在の1枚の完了後です。推論の通信上限は1回につき300秒です。解析JSONの途中切れ・形式不正には、1回だけ自動再試行します。

## 「出力が上限に達しました」と表示された場合

以前の版は出力を1,600トークンに制限していたため、複雑な画像で解析JSONが途中で切れることがありました。現在の版は通常2,048トークン、途中切れ・形式不正の場合は簡潔な記述の指示を加えて4,096トークンで1回だけ再試行します。各記述とタグ数にも目安を指定しています。

アプリを再起動して同じ画像フォルダーを開き、「未解析・失敗を解析／再開」を押してください。解析済みの成功画像は通常スキップされます。以前のエラーで保存されたものは途中の応答なので、完成したキャプションにするには再解析が必要です。

再試行前後の生出力・終了理由・上限はJSON履歴の `attempts` に保存します。最後の許可トークンでJSONが完成している場合は、終了理由が上限でも必須フィールドを検証して利用します。自動再試行でも完成しなければ、その画像をエラーとして記録し次の画像へ進みます。

## RTX 4070 12GB

初期モデルはJoyCaptionで、最大辺1024・GPU層数99です。軽い構成を使いたい場合はQwenへ切り替えられます。ほかのアプリでVRAMを使っている場合はGPU層数を減らしてください。0はCPU実行で、速度が低下します。OOMを含む起動失敗の詳細は `.local-cache/runtime.log` に残ります。性能・品質は [モデル調査](docs/MODELS.md) と `evaluations/` の実測結果を参照してください。

## 保存と再開

JSONには画像相対パス、SHA-256、解析結果、モデルの生出力、プロンプト版、処理状態、編集履歴、出力設定を保存します。画像ごとの結果受信後に一時ファイル＋置換で保存します。手動入力は400msの遅延保存、通常終了時にも保存します。

起動中に終了した処理は、次回プロジェクト読込時に未解析へ戻します。画像の内容が変わった場合は解析を無効化し、キャプションと以前の解析は履歴に保持します。失敗した1枚で全件処理は止めません。

## 検証と開発

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe tools\evaluate.py --cache .local-cache --output evaluations --model qwen4b
.\.venv\Scripts\python.exe tools\evaluate.py --cache .local-cache --output evaluations --model joy8b
```

評価コマンドは既定で赤い長方形と青い円の合成画像を作り、実機推論・JSON検証・6種類の出力を記録します。`--image` でローカル画像を指定できます。これは接続・動作試験で、成人向け画像やキャラクター／画風データセットでの品質評価とは区別しています。
